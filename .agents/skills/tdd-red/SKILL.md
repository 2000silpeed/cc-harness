# 올바른 실패를 만든다

`docs/methods/tdd.md`의 `## Red는 실패 종류를 증명하는 단계` 절만 읽는다(다음 같은/상위 수준 제목 직전까지). 입력은 검토된 계약·시나리오와 실제 테스트 러너다.

1. 테스트 수집이 가능한지 확인한다. 러너가 없으면 project-bootstrap의 승인된 준비 작업으로 돌린다.
2. 시나리오 ID와 AC를 테스트에 연결하고 사용자 관찰 결과를 assertion으로 작성한다.
3. import를 해소할 최소 stub은 허용하지만 기능 구현은 하지 않는다. 기존 코드를 대규모로 비워 실패시키지 않는다.
4. 관련 테스트를 즉시 실행하고 명령·cwd·수집 수·실패 수·실패 원인·로그를 기록한다.
5. 수집/문법/import/환경 실패는 Broken이다. 미구현 동작 때문에 실패한 증거가 없으면 Green으로 넘기지 않는다.
6. 처음부터 통과하는 테스트는 이미 구현된 동작/부실 assertion/특성화 여부를 판단한다. 억지 실패를 만들거나 전체 기존 테스트까지 실패시키지 않는다.

출력: 테스트 파일·필요한 stub·Red 증거. skip이나 의도 없는 throw로 실패 수만 맞추지 않는다.
