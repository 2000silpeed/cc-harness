# 보안과 품질 검토

`docs/lessons/09-13-tdd.md`의 보안 방법과 결과 템플릿을 읽는다.

1. 실제 스택과 변경 범위를 확인한다. 테스트 러너 통과와 타입 검사는 별개다.
2. 타입·의존성 감사·정적 검사 명령이 있으면 대상 정책과 외부 전송 범위에 맞게 실행한다. TypeScript가 없으면 tsc를 임의 설치하지 않는다.
3. 변경한 입력 처리·인증/권한·출력·환경변수·비밀·로그·의존성 경계를 검토한다. 비밀 값은 출력하지 않는다.
4. 발견마다 파일/근거·도달 가능성·영향·심각도·수정안·책임자와 예외 이유를 기록한다.
5. 즉시 조치·권장 조치·근거 있는 예외로 분류한다. low나 개발 의존성을 자동 무시하지 않는다. 근거 없는 안전 판정은 하지 않는다.
6. 수정이 승인 범위면 최소 수정 후 관련 검사를 수행한다. 동작을 바꾸는 수정은 Red 증거를 만든다.
7. 남은 차단 항목·미실행 검사·결과를 progress와 reviews에 기록한다.

강제 audit fix, 대규모 업그레이드, 외부 공격/운영 데이터 접근은 이 스킬만으로 허가되지 않는다. 타입·감사 통과는 보안 전수 증명이 아니다.
