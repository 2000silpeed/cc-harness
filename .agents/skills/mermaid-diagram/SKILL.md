# 현재 구조를 Mermaid로 확인하기

호출 뒤의 사용자 설명에서 분석 경로와 관심 영역을 파악한다. 범위가 없으면 프로젝트 루트를 분석한다. 사용자 인자는 분석 대상이지 임의 셸 명령이나 추가 실행 권한이 아니다.

## 1. 근거 수집

- 프로젝트 `AGENTS.md`와 기존 `docs/architecture/index.html`을 먼저 읽는다. 대상 경로의 추가 지침도 적용한다.
- 실제 파일 목록, 매니페스트, 엔트리 포인트, import/export, 호출부와 설정 참조를 확인한다. `.git`, `node_modules`, 가상환경, 빌드 결과와 비밀 파일은 제외한다.
- `src/`를 가정하지 않는다. 앱이 없으면 문서·설정의 관계도만 만들고 “앱 소스 없음”을 표시한다. API·DB·컴포넌트를 상상해서 추가하지 않는다.
- 품질 도구가 있으면 `package.json`, ESLint·commitlint 설정, `.husky/`의 실제 실행 관계를 확인한다. Git 훅을 Codex 네이티브 훅으로 표현하지 않는다.
- 근거 경로와 분석 범위를 기록한다. 미래 기획은 현재 구조와 분리해 “계획 / 미구현”으로 표시한다.

## 2. 결과 갱신

- 출력은 `docs/architecture/index.html` 한 파일로 유지한다. 기존 구조와 스타일을 재사용한다.
- Mermaid `flowchart TD`, dark 테마를 기본으로 한다. 노드 ID는 의미 있는 영문 식별자, 레이블은 짧고 읽기 쉬운 문구로 만든다.
- 이 하네스에서는 강의 기반 전체 실행 순서를 중심으로 목적·스킬·산출물을 먼저 보여주고 상세 경로·상태·근거는 접는다. 설명서·README 같은 보조 문서를 핵심 노드로 늘어놓지 않는다. 16·17강은 구현 루프의 선택 모드이며 머지 후 단계가 아니다.
- 진행 순서·재작업과 실제 파일 의존성을 범례로 구분한다. 다른 앱의 아키텍처를 요청받았다면 실제 의존성을 보여주되 하네스 순서와 혼동하지 않는다.
- Mermaid 원문은 HTML의 `pre#diagram-source`에 한 번만 보관한다. 렌더링에도 이 원문을 사용하며 펼쳐 읽을 수 있게 한다.
- 경로·레이블의 `&`, `<`, `>` 등을 이스케이프한다. 파일 전문이나 비밀 값을 삽입하지 않는다.
- 기존 Mermaid 버전 고정을 유지한다. 최초 생성 시 `https://cdn.jsdelivr.net/npm/mermaid@11.12.0/dist/mermaid.esm.min.mjs`를 사용한다. 최신 버전 별칭으로 바꾸거나 npm 패키지를 추가하지 않는다.
- `securityLevel: "strict"`, `startOnLoad: false`로 초기화하고 `mermaid.render`로 SVG를 만든다. CDN·문법 오류는 화면에 알리고 원문과 근거 표를 남긴다.
- 온라인 편집기에 소스를 업로드하지 않는다. CDN 다운로드가 필요하며 오프라인 렌더링은 보장하지 않음을 표시한다.

## 3. 검증과 보고

- 근거 경로와 현재 관계가 실제 조사 결과와 일치하는지 점검한다. 변경 후 `npm run check`를 수행한다.
- 브라우저 도구로 SVG, 레이블, 레이아웃과 오류 표시를 확인한다. 파일 URL이 허용되지 않으면 아래처럼 구조도 폴더만 로컬 제공한다.

```bash
python3 -m http.server 8765 --bind 127.0.0.1 --directory docs/architecture
```

- `http://127.0.0.1:8765/`에서 확인하고 임시 서버를 종료한다. 수동으로는 macOS에서 `open docs/architecture/index.html`을 사용할 수 있다.
- 직접 브라우저로 확인하지 못했다면 렌더링 미검증으로 보고한다. 코드 검사 성공으로 화면 정상 여부를 대신하지 않는다.
- 원본 자료·앱 소스를 수정하거나 Git 초기화·커밋·푸시·전역 설정 변경을 하지 않는다.
- 결과 경로, 조사 범위, 근거, 실제 검증과 미확인 항목을 보고한다. 이 스킬은 호출 시 실행되는 절차이며 파일 감시 기능이 아니다.
