# 프로젝트 기반 준비

`docs/harness/lifecycle.md`의 환경 준비와 빈 저장소 절차, `docs/harness/reuse.md`, `docs/methods/project-foundation.md`를 읽는다.

## 두 가지 모드

- **하네스 준비:** 짧은 AGENTS, 기존 스킬 연결, 실제 파일에 맞는 lint/format/commit 검사와 문서 흐름.
- **앱 기반 준비:** 승인된 PRD·기술안·준비 이슈를 확인한 후 최소 엔트리·런타임·러너·명령 구성. 사용자 승인 없는 프레임워크 선택은 하지 않는다.

## 절차

1. 대상 경로·지침·Git 변경·의존성·실제 명령·기존 CI를 조사한다. npm/React/TypeScript라고 가정하지 않는다.
2. 설치된 도구는 재사용한다. 없는 의존성은 목적·범위·기존 대안을 검토하고 승인된 작업 안에서만 추가한다.
3. 기존 AGENTS와 package/훅 설정을 필요한 부분만 병합한다. 새 저장소 생성·브랜치·커밋·원격 연결은 명시적 요청 범위에서만 한다.
4. Git 훅과 Codex 이벤트 훅을 구분한다. Codex 신뢰 승인을 우회하지 않는다. 구조도용 디자인 검사기를 제품 전체 검사로 복사하지 않는다.
5. 앱 기반 모드에서는 실제 실행과 테스트 수집을 확인한다. 이 확인은 사용자 기능 완성이나 TDD Green이 아니다.
6. 정상·위반 검사를 대상 환경에 맞게 수행하고 README에 명령·전제·미실행 항목을 남긴다. 파괴적인 실패 실험은 격리 환경에서 한다.

출력: 적용 파일 목록, 실제 실행 명령, 검사 증거, 필요한 사용자 결정. 문서·검사 구성만 필요한 저장소에 예제 앱을 만들지 않는다.
