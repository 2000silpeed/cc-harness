# 프로젝트 기반 준비

대상과 모드를 먼저 확정한다. 절은 지정 제목부터 다음 같은/상위 수준 제목 직전까지만 선택한다.

- **하네스 준비:** `docs/harness/lifecycle.md`의 `## 3. 대상과 하네스 위치`와 `docs/methods/project-foundation.md`의 `## 입력과 조사`를 읽는다. 품질 도구 연결은 `## 커밋 전 품질 체인`·`## 설치와 연결`, 위반 검증은 `## 실패를 포함한 검증`, 인계는 `## 완료와 인계`를 그 작업 시점에만 추가한다.
- **이식·갱신:** `docs/harness/reuse.md`에서 새 PC 준비는 `## 2. 새 PC 준비`, 복사는 `## 3. 다운로드와 이식`, 별도 설정은 `## 4. 자동 복사와 별도 설정`, 첫 실행은 `## 5. Codex를 연 다음 첫 입력`, 갱신은 `## 9. 개선판 업데이트`, 충돌·소유 판정은 그 안의 `### ADOPT/RESUME reconciliation 경계`만 선택한다.
- **앱 기반 준비:** 승인된 PRD·기술안·준비 이슈를 확인하고 `docs/harness/lifecycle.md`의 `## 8. 앱을 처음부터 만드는 경우`와 project-foundation의 `## 입력과 조사`·`## 설치와 연결`·`## 실패를 포함한 검증`·`## 완료와 인계`를 현재 작업이 도달할 때 순서대로 읽는다.

대상 `AGENTS.md`를 작성·갱신할 때만 reuse의 `## 5. Codex를 연 다음 첫 입력`을 읽고 공통 정책 링크, 메인/유한 작업자 역할, 새 최소 컨텍스트, 독립 검증자, 재귀 위임 금지, 도구 부재 시 메인이 대신하지 않는 계약을 기존 지침에 병합한다.

registry는 등록 복사나 `check-harness` 실행에 기계적으로 사용하고 모델 컨텍스트로 전수 적재하지 않는다.

1. 대상 경로·지침·Git 변경과 소유·의존성·실제 명령·CI를 조사한다. npm/React/TypeScript를 가정하지 않는다.
2. 기존 도구·AGENTS·package/훅 설정을 필요한 부분만 병합한다. 새 의존성·프레임워크는 승인 범위와 실제 대안을 확인한다.
3. 새 저장소·브랜치·커밋·원격 연결은 명시적 요청 범위에서만 한다. Git 훅과 Codex 이벤트 훅을 구분하고 신뢰 승인을 우회하지 않는다. 구조도용 디자인 검사기를 제품 전체 검사로 복사하지 않는다.
4. 앱 기반 모드는 최소 엔트리·런타임·러너·명령을 구성하고 실제 실행과 테스트 수집을 확인한다. 이는 기능 완성이나 TDD Green이 아니다.
5. 정상·위반 검사를 실제 환경에 맞게 수행한다. 파괴적 실패는 격리하고 README에 명령·전제·미실행을 기록한다.

출력은 적용 파일, 실제 명령·결과, 남은 사용자 결정이다. 문서·검사만 필요한 저장소에 예제 앱을 만들지 않는다.
