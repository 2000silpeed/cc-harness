# 최소 구현

`docs/methods/tdd.md`의 `## Green은 테스트를 바꾸지 않는 최소 구현` 절만 읽고(다음 같은/상위 수준 제목 직전까지), UI가 있으면 대상 design.md와 design-system 스킬을 읽는다.

1. 미구현 실패인 Red 증거와 승인된 시나리오를 확인한다.
2. 실패 하나씩 필요한 동작만 구현한다. 테스트 기대값·계약·AC를 통과 편의상 바꾸지 않는다.
3. 각 변경 후 관련 테스트와 회귀 범위를 확인한다. 새 실패가 생기면 자신의 변경부터 조사한다.
4. 해당 이슈의 필수 테스트가 통과할 때까지 진행한다. 미래 기능·추측한 예외·불필요한 추상화를 덧붙이지 않는다.
5. coverage가 설정돼 있으면 누락 분기를 시나리오 후보로 읽는다. 숫자만 높이거나 무근거 제외하지 않는다.
6. 실제 명령과 결과를 남겨 ac-verifier에 인계한다. 테스트 통과를 AC 전체 충족이나 시각 검증 완료로 표현하지 않는다.

테스트 자체 오류나 요구사항 변경이 필요하면 이유를 기록하고 시나리오 게이트로 돌아간다. UI 검사 범위와 실제 브라우저 확인을 분리한다.
