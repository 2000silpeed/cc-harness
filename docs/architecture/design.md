# 구조도 화면 디자인 정의서

## 출처와 적용 범위

화면 기준은 현재 존재하는 `docs/architecture/index.html`의 HTML/CSS다. 제공된 Figma나 스크린샷이 없어 이미지에서 추출했다고 주장하지 않고 기존 코드에서 기준을 추출했다. 화면을 재디자인하지 않으며, PM 앱의 디자인 승인이나 요구사항 확정을 대신하지 않는다.

## 화면 구성

어두운 단일 열 문서. 아이디어 → 기반 → 요구사항·디자인 → 설계·이슈 → 이슈별 TDD → E2E·CI·머지 순으로 카드를 배치한다. 각 카드에는 목적·스킬·다음 단계 산출물을 먼저 표시하고 승인·세부 상태는 접어 둔다. 설명서·README·현재 HTML 같은 보조 산출물은 흐름 노드로 넣지 않는다.

헤더의 단계 링크는 해당 카드로 이동한다. tdd-loop와 tdd-auto-loop는 이슈별 TDD 카드 안에서 반복 방식 선택으로 설명한다. 배포·운영은 main 머지 이후 별도 승인·검증이 필요한 인계로 구분한다. 전체 Mermaid 도식과 원문은 보조 정보로 접어 둔다. 최대 폭 1180px와 기존 색상·타이포그래피·간격을 유지하고, 600px 이하에서는 여백을 줄인다.

헤더에는 15개 스킬과 독립형 방법론을 안내하고, footer에는 새 PC에서 시작할 수 있는 `docs/harness/reuse.md` 링크를 둔다. 스킬 등록과 실제 제품 구현·머지·배포는 구분한다.

## 공통 기준

- [색상](../design-system/colors.md): 배경·본문·강조·상태 색과 테두리.
- [타이포그래피](../design-system/typography.md): 시스템 폰트·제목·본문·코드.
- [간격과 배치](../design-system/spacing.md): 여백·너비·둥근 모서리·줄바꿈.
- [컴포넌트](../design-system/components.md): 구성과 기본·성공·오류·포커스 상태.

현재는 일반 CSS를 사용한다. 문구 수정 때문에 Tailwind 클래스를 도입하거나 React 앱을 새로 만들지 않는다. 기능 구현용 design.md는 추후 실제 참고 이미지와 승인된 기능 범위가 준비되면 `docs/features/{feature}/design.md`에 별도로 작성한다.

## 변경 시 검증

`npm run design:check`로 CSS 속성·값의 기준 이탈을 확인한다. 화면을 변경했다면 넓은 화면과 600px 이하 화면, 긴 경로, 키보드 포커스, Mermaid 로딩 성공·실패를 실제 확인한다. 정적 검사 통과를 시각 검증 완료라고 보고하지 않는다.
