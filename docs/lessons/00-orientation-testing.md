# 강의소개·특강 — 전체 방향과 테스트 읽는 방법

## 강의소개 7쪽

강의 목표는 특정 프레임워크를 가져다 쓰는 것이 아니라, 지침·검증·피드백 루프·사람의 개입점을 갖춘 자신의 하네스를 만드는 것이다. 환경 준비 → 요구사항·설계 → 이슈별 TDD → E2E·PR·CI·main 머지가 주요 범위다. 16·17강의 반복 자동화는 그 절차를 재사용하는 확장이다.

소개 도식은 15강 코스로 표현하며 Mermaid 자동 훅을 언급하지만, 현재 파일 묶음에는 17강까지 있다. 도식의 예고를 설치 완료로 해석하지 않는다. 현재 Mermaid는 요청 시 갱신하는 스킬이고 자동 감시 훅은 아니다. 배포·운영은 소개의 대상 독자 맥락에 나타나지만 상세 배포 절차를 다루는 별도 강의는 없다. 전체 사이클 설명서에서는 그 부분을 보완 인계 단계로 표시한다.

Git/GitHub, npm·터미널의 기본 사용이 전제이며 TS·단위 테스트 경험은 도움이 된다. 완성된 대형 앱이나 한 번 클릭하는 마법의 자동화가 아니라 작은 기능을 끝까지 검증하는 체계를 얻는 과정이다.

## 특강 24쪽 — 테스트 코드의 의미

테스트는 사전 조건에서 행동했을 때 기대 결과가 나오는지 자동으로 비교하는 코드다. 자판기·덧셈·장바구니는 이를 설명하는 예이며 제품 요구사항은 아니다.

### 자연어를 테스트로 바꾸는 방법

1. Given에 초기 데이터와 환경을 적는다.
2. When에 사용자 행동 또는 호출 하나를 적는다.
3. Then에 관찰 가능한 결과를 적는다.
4. 같은 구조를 Arrange·Act·Assert로 코드화한다. 용어를 외우는 것보다 준비·행동·검증을 분리한다.
5. 실패 로그의 예상값·실제값·실패 지점을 읽고, 환경 오류인지 계약 위반인지 판단한다.

React 예시는 버튼을 클릭한 뒤 표시된 카운트, 비동기 응답 전 로딩 문구와 응답 후 사용자 이름을 검증한다. 내부 state보다 사용자 관찰 결과를 검사한다. 즉시 존재하는 요소와 나중에 나타나는 요소를 구분하고 비동기 완료를 기다린다. 대상 테스트 라이브러리가 제공하는 조건 기반 대기를 사용하며 임의 sleep으로 타이밍을 맞추지 않는다.

### Matcher·대역·FIRST

- 원시 값/참조 동일성과 객체 내용 비교는 다르다. 오류·비동기 거부·DOM 존재·호출 횟수에 맞는 assertion을 선택한다.
- Stub은 정해진 응답을 제공하고 Mock은 필요한 상호작용을 검증한다. 실제 결제·메일·외부 네트워크는 테스트에서 안전한 대역을 사용한다.
- 날짜·난수·외부 상태를 제어해서 재현 가능하게 한다. 대역만 통과하고 실제 경계 연동이 검증되지 않은 부분은 별도 통합/E2E 테스트로 보완한다.
- FIRST: 빠르게, 독립적으로, 반복 가능하게, 자동 판정 가능하게, 적시에 작성한다. 원문의 1초 설명은 빠른 피드백의 예이지 모든 테스트의 고정 시간 제한이 아니다.
- 테스트는 회귀 방지·리팩터링 안전망·실행 가능한 명세다. 통과했다는 사실만으로 모든 요구사항을 충족했다고 판단하지 않는다.

### 초보자 확인 과제

실제 승인된 AC 하나를 골라 GWT를 작성하고, 어떤 결과를 assert할지 설명한다. 네트워크/시간 중 통제할 의존성을 하나 찾는다. 테스트를 실행해 실패 이유를 설명한 뒤 최소 구현으로 통과시킨다. 제품 테스트 러너가 없는 이 저장소에 학습 예제 앱을 임의로 추가하지 않는다.
