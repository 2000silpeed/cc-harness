# 하네스 지원 기능과 책임

이 표는 실행 절차의 지원 범위다. 등록된 스킬과 문서가 존재한다는 사실을 제품 완료나 외부 서비스 연결 완료로 해석하지 않는다.

| 책임        | 진입 스킬         | 입력 → 결과                            | 완료 증거                            |
| ----------- | ----------------- | -------------------------------------- | ------------------------------------ |
| 전체 조율   | harness-cycle     | 목적·현재 상태 → 단계·승인·다음 행동   | progress와 실제 파일 일치            |
| 개발 기반   | project-bootstrap | 기존 도구·승인 기술안 → 지침·러너·검사 | 최소 실행과 정상/위반 검사           |
| 기획        | feature-planner   | 아이디어·인터뷰 → spec·PRD·ADR·이슈    | 요구사항·기술안·범위·이슈 승인       |
| 디자인      | design-system     | 제품·화면·참고 → 화면과 공통 기준      | 정적 검사·시각 검토·사용자 판단 구분 |
| 구조도      | mermaid-diagram   | 실제 관계 → 실행 지도                  | 경로·렌더·오류 상태 확인             |
| 테스트 설계 | test-scenarios    | AC → 함수/API 계약·정상/경계/예외      | 시나리오 검토와 추적 가능성          |
| 실패 증거   | tdd-red           | 시나리오 → 테스트·최소 stub            | 기능 미구현에 의한 실제 실패         |
| 구현        | tdd-green         | 올바른 Red → 최소 구현                 | 고정된 테스트와 관련 회귀 통과       |
| 독립 판정   | ac-verifier       | AC·구현·증거 → 기준별 판정             | 구현자와 분리된 pass/fail/unverified |
| 구조 개선   | tdd-refactor      | Green·AC → 동작 보존 개선              | 전체 회귀와 변경 이유                |
| 보안        | security-review   | 실제 경계·도구 → 위험·조치             | 재스캔·잔여 위험·미검증              |
| 단계별 반복 | tdd-loop          | 승인 이슈 → 순서대로 수행              | 단계별 결과·승인 유지                |
| 제한 자동화 | tdd-auto-loop     | 유한 이슈·상한·위임 → 단계별 결과      | 독립 검증·횟수·STOP 준수             |
| 전체 여정   | e2e-write         | 통합 기능 → 진입점 시나리오            | 격리된 데이터·실패 증거·재현         |
| 전달        | create-pr         | 검증 변경·허용 범위 → PR/로컬 인계     | 실제 head·CI·리뷰·원격 권한          |

## 연결의 원칙

요구사항 ID → AC → 시나리오 ID → 테스트 → 실행 로그 → 독립 판정 → 진행 기록을 연결한다. 코드나 계약이 바뀌면 이전 증거가 여전히 유효한지 확인한다. 파일 이름이나 날짜가 최신이라는 이유만으로 완료로 승격하지 않는다.

하네스 준비와 앱 기반 생성, 테스트 통과와 AC 충족, 사용자 시각 수락과 결함 해결, 머지와 배포를 구분한다. 배포는 플랫폼·비용·데이터·복구 계획과 별도 권한이 필요하다.

## 제공하지 않는 자동 설치

프레임워크·DB·인증·클라우드·전역 Codex 설정·플러그인·MCP·독립 에이전트 런타임·원격 CI·디자인 합성 엔진은 이식 도구가 설치하지 않는다. 필요할 때 대상 환경을 확인해 선택·연결·검증한다. 방법론의 예시 값을 제품 요구사항으로 복사하지 않는다.

재사용은 [reuse.md](reuse.md), 승인과 반복은 [lifecycle.md](lifecycle.md), 실제 검증은 [verification.md](verification.md)를 따른다.
