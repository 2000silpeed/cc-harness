# 다른 프로젝트에 가져가는 방법

## 복사와 설정을 분리한다

이식 도구는 등록된 스킬과 참조 문서·검증 도구만 복사한다. **제품 파일·PM 인터뷰·강의 PDF·전역 설정·AGENTS·package.json·Git/Codex 훅은 자동으로 덮어쓰지 않는다.** 대상의 런타임이나 프레임워크도 선택하지 않는다.

## 1. 복사 계획 확인

하네스 원본 저장소에서 실행한다. 대상 폴더는 미리 존재해야 한다.

```sh
node scripts/install-harness.mjs --target /absolute/path/to/project
```

기본은 dry-run이다. 생성할 파일·이미 동일한 파일·충돌을 출력하며 아무것도 쓰지 않는다. 대상에 내용이 다른 동명 파일이 있으면 중단한다. 심볼릭 링크를 따라 대상 밖에 쓰지 않는다. 승인 없이 덮어쓰기 옵션을 제공하지 않는다.

## 2. 계획대로 복사

```sh
node scripts/install-harness.mjs --target /absolute/path/to/project --apply
```

스킬은 `.agents/skills/`, 참조 문서는 `docs/`, 이식/검사 도구는 `scripts/`에 들어간다. PDF와 사례 파일은 제외한다. 같은 내용은 건너뛰므로 반복 실행해도 중복 파일을 만들지 않는다. 복사 중 오류가 나면 기존 파일을 삭제하지 말고 출력된 생성 목록을 확인한 뒤 재실행한다.

## 3. 대상 프로젝트에 맞게 연결

1. 대상의 기존 AGENTS를 읽고 전체 사이클 설명서의 위치와 허용 작업 범위를 짧게 연결한다.
2. 기존 lint·format·test·build 명령을 조사한다. 원본 package.json을 그대로 복사하지 않는다.
3. 필요할 때 project-bootstrap으로 기존 설정을 병합한다. 디자인 값과 검사기 대상도 새 제품에 맞게 만든다.
4. Codex 훅은 선택한 검사 명령이 실제 동작한 뒤 기존 훅과 병합하고 사용자 신뢰 승인을 받는다. 현재 `.codex/hooks.json`은 구조도 전용이므로 배포 파일에서 제외한다.
5. 새 Codex 세션에서 프로젝트 스킬 발견 여부를 확인하고 `$harness-cycle`로 대상과 범위를 지정한다.

앱이 없는 새 폴더라면 아이디어·기술안 승인 전에 앱 스택을 임의 설치하지 않는다. 이식 자체로 앱 테스트나 CI가 만들어지지 않는다.

## 4. 이식 결과 확인

대상 프로젝트에서:

```sh
node scripts/check-harness.mjs
```

등록된 파일·스킬 이름·문서 연결·224쪽 커버리지 선언을 검사한다. PDF가 함께 있으면 원본 해시도 확인하고, 이식본처럼 PDF가 없으면 해시 검사를 건너뛴 수를 표시한다. 페이지 목록의 구조 검사는 사람이 실제로 읽었다는 증거를 대신하지 않으며, 실제 판독 기록은 강의별 설명서에 있다.

이식은 의존성 설치·Codex 런타임 신뢰·독립 에이전트 실행·제품 TDD를 보장하지 않는다. 파일 복사 확인과 새 프로젝트 실제 동작 확인을 구분한다.

## 충돌을 만났을 때

동명 스킬이 이미 있으면 내용과 사용 중인 참조부터 비교한다. 기존 것을 무단 삭제하지 않는다. 필요하면 사용자가 승인한 병합으로 해결한 뒤 다시 dry-run한다. 원본 하네스 변경분을 가져올 때도 같은 절차를 사용한다.
