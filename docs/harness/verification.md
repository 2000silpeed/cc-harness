# 하네스 검증 기록

이 문서는 스킬·설명서 등록 검증과 실제 제품 실행을 구분한다. 검증일: 2026-09-12. 이식본에 포함된 이 기록은 원본 하네스의 검사 결과이며 새 대상 프로젝트의 성공 증거가 아니다.

## 등록과 재사용 검사

| 검사         | 결과와 범위                                                                                                                             |
| ------------ | --------------------------------------------------------------------------------------------------------------------------------------- |
| 자료 대조    | 18개 자료, 224쪽. 강의별 페이지 판독 표와 registry의 대응을 확인했다. 18강은 예고만 있고 원본이 없어 분석 완료에 포함하지 않았다.       |
| 등록 검사    | `node scripts/check-harness.mjs`: 15개 스킬, 18개 자료, 224쪽 선언, 원본 PDF 해시 18개 통과. 파일·링크·페이지 선언의 구조 검사다.       |
| 스킬 형식    | skill-creator의 `quick_validate.py`로 15개 모두 통과.                                                                                   |
| Codex 발견   | 로컬 `codex app-server`의 `skills/list` 조회: 15개 모두 repo 범위, enabled=true, errors=[] 확인. 모델 호출이나 제품 실행은 하지 않았다. |
| 이식 dry-run | 빈 임시 대상에 변경 없이 복사 계획만 출력.                                                                                              |
| 이식 적용    | 등록된 32파일 복사 성공. 재실행은 새 파일 0개로 멱등성 확인.                                                                            |
| 이식본 검사  | 복사한 `scripts/check-harness.mjs` 실행 성공. PDF 미포함 18개를 해시 검사 건너뜀으로 정확히 표시.                                       |
| 충돌 방어    | 다른 내용의 기존 SKILL.md가 있으면 종료 코드 1. 기존 내용 보존, 다른 파일도 쓰지 않음.                                                  |
| 경로 방어    | 대상 내부 심볼릭 링크 및 없는 대상 폴더를 거부. 링크 외부 디렉터리 변경 없음.                                                           |
| 부정 검사    | 임시 이식본의 페이지 목록을 중복·누락시키면 등록 검사 실패 확인. 원본 registry는 변경하지 않음.                                         |

이식 검사는 Node 내장 fs·assert·child_process로 만든 독립 임시 폴더에서 수행했다. 추가 의존성이나 앱 테스트 프레임워크는 설치하지 않았다. 재현 시 [이식 방법](reuse.md)의 dry-run → apply → 이식본 검사 순서를 사용한다. 충돌·링크·잘못된 페이지 목록은 반드시 폐기 가능한 별도 임시 대상에서 만든다.

## 독립 방법론 검토

- 기획 검토: 빈 프로젝트·미승인 요구사항·Figma 없음·기술 선택 위임·즉시 GitHub 등록 요청 시나리오를 별도 검토자가 대조했다. 기술 위임과 요구사항 승인 분리, 원본 G1–G4 유지, 기존 화면이 없어도 UI 요구사항에 따라 디자인을 작성하도록 보완했다.
- 자동 루프 검토: 잘못된 base·미커밋 변경·시나리오 4개·Green 3회 실패·테스트 수정 요청을 원문 17:p7과 대조했다. STOP 우선순위, 전체 회귀 검사, 실패 횟수 초기화 우회 금지, 두 루프의 판단 자동화 차이를 보완했다.
- 이는 문서와 가상 입력의 독립 검토다. 실제 앱의 격리 에이전트 자동 실행이나 실제 AC 통과를 뜻하지 않는다.

## 화면 확인

Chrome에서 로컬 HTTP로 `docs/architecture/index.html`을 열어 시작 화면, 6단계 접근성 구조, 접힌 전체 도식의 펼침과 Mermaid 렌더링, 이슈 반복 화살표를 확인했다. 도식과 기본 단계 설명을 분리하고 각 단계에 스킬·인계 산출물을 표시했다.

내장 브라우저 연결은 `privileged native pipe bridge is not available; browser-client is not trusted` 오류로 사용할 수 없어 Chrome으로 확인했다. 신뢰 설정을 우회하지 않았다. 이번 화면 확인은 데스크톱 기준이며 모바일 반응형·전체 키보드 탐색은 별도 미검증이다.

## 최종 통합 검사

`npm run check` 최종 종료 코드 0: ESLint, 디자인 정적 기준 84개 선언, 하네스 등록, Prettier 모두 통과했다. 첫 검사에서 Markdown 2파일의 서식 오류가 나와 해당 파일을 다시 포맷하고 통합 검사를 재실행했다. 원격 CI나 앱 테스트는 아니다.

`shasum -a 256 -c tmp/pdfs/course/source-before.sha256`로 PDF 18개, 원본 워크플로우 1개, PM 인터뷰·최초 정의·확정 명세 3개 모두 OK를 확인했다. 기존 인터뷰 내용과 승인 상태를 변경하지 않았다. 이 기준 해시 파일은 원본 작업 환경의 임시 검증 자료이며 이식 대상에는 복사하지 않는다.

## 제품 실행 상태

- 실제 앱 구현·앱 테스트·빌드·E2E: 미실행. 현재 저장소에는 앱이 없다.
- GitHub 이슈·PR·CI·머지·배포: 미실행. 외부 작업 요청이 아니다.
- Codex 디자인 훅: 설정과 명령 수동 검증은 이전에 수행. 사용자 신뢰와 실제 이벤트 발화는 미검증.
- 기존 PM 인터뷰: 내용·승인 상태 변경 없음. SHA-256 대조 통과.

등록 구조 검사나 스킬의 발견 여부는 제품 작업 성공을 보장하지 않는다. 자동 모드의 실제 격리 에이전트 전체 사이클은 승인된 대상 앱에서 별도 검증해야 한다.
