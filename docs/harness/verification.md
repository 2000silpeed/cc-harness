# 하네스 검증과 배포 경계

## 검증 대상

이식본에 포함된 검증 설명은 하네스 도구의 범위를 설명한다. 새 프로젝트의 제품 성공 증거가 아니다. 최신 실제 명령 결과는 대상 프로젝트의 progress에 기록한다.

| 검사           | 확인하는 것                                             | 보장하지 않는 것                 |
| -------------- | ------------------------------------------------------- | -------------------------------- |
| check-harness  | registry 형식·안전한 경로·등록 파일·스킬 이름·문서 참조 | 모델 실행·제품 구현              |
| 설치 dry-run   | 계획·충돌·쓰기 없음                                     | 앱 설정 병합                     |
| 설치 apply     | 허용된 등록 파일만 복사                                 | package·AGENTS·훅 자동 구성      |
| 재실행         | 동일 파일 건너뜀·기존 내용 보존                         | 차이가 있는 파일의 자동 업데이트 |
| 부정 검사      | 충돌·잘못된 경로·누락 참조 거부                         | 모든 운영 환경의 안전성          |
| Codex 발견     | 해당 제품에서 스킬을 읽을 수 있음                       | 독립 에이전트나 훅 실제 실행     |
| 제품 통합 검사 | 그 버전의 설정·단위·빌드·브라우저 결과                  | AC 전체 충족·원격 CI·배포        |

## 재현 절차

Node가 설치된 원본에서 실행한다.

```sh
node scripts/check-harness.mjs
```

빈 임시 제품 폴더를 만들고 [reuse.md](reuse.md)의 dry-run → apply → 대상 check-harness → 다시 apply 순서를 수행한다. 등록 목록 외 PM 소스·package·AGENTS·훅·개인 데이터가 생성되지 않았는지 확인한다.

의존성이 설치된 원본에서는 다음 회귀 검사를 사용한다.

```sh
npx vitest run tests/unit/harness-portability.test.ts
```

충돌·심볼릭 링크·손상 registry 실험은 폐기 가능한 임시 대상에서만 수행한다. 운영 제품에 실패 fixture를 주입하지 않는다. 검사마다 cwd·명령·종료 코드·대상 SHA·로그 위치를 남긴다.

## 현재 배포 상태의 해석

### 2026-09-13 로컬 검증

- macOS·Node 24.14.1에서 등록 검사: 스킬 15개·등록 파일 32개 통과.
- 이식 회귀 44개 통과: 실제 배포 목록, dry-run 무변경, apply, 재실행, 충돌 보존, 누락 참조, 경로·심볼릭 링크, 빈 스킬 설명 거부를 검사했다.
- 커밋 예정 파일을 `git write-tree`·`git archive`로 별도 임시 폴더에 추출하고 빈 제품에 dry-run → apply → 대상 검사 → 재실행을 확인했다. package·AGENTS·훅·PM 소스·데이터가 복사되지 않았다. 로그: 원본의 `tmp/harness-release-{dry-run,apply,repeat}.log`.
- 로컬 작업 트리의 `npm run check` exit 0: 단위 284개·브라우저 85개, lint·디자인·하네스·서식·타입·빌드 통과. 로그: 원본의 `tmp/harness-standalone-check.log`.
- 이 전체 검사는 **미커밋 PM-07 구현이 있는 로컬 작업 트리** 기준이다. 원격에 포함할 PM 준비 상태의 전체 검사 통과를 뜻하지 않는다. 기존 독립 AC 실패도 해결하지 않았다.
- 현재 문서·스킬·검사 코드에서 이전 자료 번호·이전 방법론 경로 참조가 남지 않았음을 검색 확인했다. 구조도 CSS는 유지했고 정적 검사를 통과했으나 이번 문구 변경의 브라우저 시각 검수는 하지 않았다.
- 로그와 임시 추출본은 로컬 증거이며 배포 파일이 아니다. Windows 실기기·원격 CI·배포는 수행하지 않았다. 기존 5173·5174 서버와 브라우저 데이터는 유지했다.

재사용 문서는 등록된 스킬과 함께 배포한다. PM 사례 앱은 이식 대상이 아니다. 원본 저장소의 Git에 포함된 PM-07 준비 테스트와 로컬 미커밋 구현은 서로 다르며, 이 때문에 하네스 이식 통과와 원본 PM 전체 검사 상태도 구분해야 한다. 현재 구분은 원본 README와 PM 진행 기록을 따른다.

Windows 실기기, 새 PC 계정 인증, 실제 Codex 훅 신뢰, 플러그인/MCP, 외부 디자인 엔진, 원격 CI·배포는 별도 환경에서 확인해야 한다. 검증 결과가 없으면 미검증으로 남긴다.

## 갱신 시 확인

문서 이동 시 registry·스킬·AGENTS·README·구조도의 참조를 함께 갱신한다. 실행 가능한 기준과 중단 조건을 유지하고, 설명의 출처 정리를 이유로 테스트·승인·검증 기준을 약화하지 않는다. 신규 문서 배포 후 실제 빈 대상에서 이식 검사를 다시 수행한다.
