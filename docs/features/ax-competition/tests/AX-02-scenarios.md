## CLI 계약

`node scripts/ax-session.mjs question --ledger <JSONL> --role <nonempty> --topic <nonempty> --text <nonempty> [--follow-up <nonempty reason>]`: 동기 프로세스. role/topic은 trim 후 Unicode NFC로 정규화한 쌍을 중복 키로 쓴다. 최초 질문은 UTC 시각·키·원문·질문을 JSONL에 추가하고 종료 0이다. 중복은 원장 바이트 불변, 종료 2다. 새 정보를 얻을 명시적 follow-up 이유가 있는 재질문은 그 이유와 질문을 새 기록으로 추가하고 종료 0이다. 빈 필수 입력·손상된 원장·I/O 실패는 종료 1이고 원장 불변이다. 기존 모든 행의 schema와 정규화 키 관계를 검증한다. 다중 프로세스에서는 exclusive-local lock(`wx`)을 사용하고 잠금 안에서 동일 부모의 임시 파일을 원자적으로 교체한다. 잠금 충돌은 실패 처리하며 잠금은 소유한 실행만 정리한다. 표준 출력은 상태·경로·키·건수만 포함한다.

`node scripts/ax-session.mjs record-result --source <file> --result <JSON file> --out <root>`: 동기 프로세스. result 객체의 `agent_sha256`는 현재 source 바이트 SHA-256과 정확히 맞아야 한다. source→result→source 순서로 읽어 source 변경을 감지한다. 성공 시 `<out>/<sourcehash>/<resulthash>/` 아래 source와 원래 result 바이트의 snapshot, 두 해시·UTC 시각·원래 경로가 있는 manifest를 저장하고 종료 0이다. 기존 bundle은 덮지 않고 종료 2다. 필수 필드 누락·불일치·손상 JSON·I/O 실패는 종료 1이며 완료 판정을 남기지 않는다. bundle 디렉터리를 배타적으로 생성한 후 쓰기 실패는 부분 산출물을 유지하고 오류를 알린다. 원본 파일은 변경하지 않는다. 표준 출력은 상태·경로·해시만 포함하며 결과 본문이나 private 자료를 출력하지 않는다. 저장된 declared hash는 실제 검사 실행 또는 그때 사용된 source의 증명이 아니다.

종료 2는 계약상 중복/기존 bundle 또는 동시 lock 충돌, 종료 1은 잘못된 입력·읽기/쓰기 실패다. 파일 권한과 디렉터리/심볼릭 링크 등 경로 안정성은 독립 보안 검토 대상이다. source의 실제 실행 정체와 freeze 시점 확인은 호출자·검증자의 책임이다.

## 미정·제외

실제 인터뷰 횟수, API·플랫폼 연결, 에이전트 실행 증명, 대회 제출과 제품 출시 수락은 제외한다. 임의 질문 수 상한으로 중요한 미결 게이트를 통과시키지 않는다. 실패한 쓰기의 부분 bundle은 수동 조사 대상이며 완료 증거가 아니다.
