# cc-harness 아키텍처 재설계 잔여 범위 PRD v2 · 최신 G4/G5 계약 PASS

- 입력: [v2 요구사항](spec-fixed-v2.md) R7–R9, v1 AR-01~03 결과, 현재 저장소 코드·문서. 새 앱 화면은 없다.

## 사용자 흐름과 세 안

### [GATE 2] 기술 결정 · policy-delegated

B를 택한다. 사용자 원문은 기존 재설계를 끝까지 진행하라는 결과·가역 구현 승인이고, 세부 경계 선택은 AI 판단이다. B는 기존 CLI·검사와 승인 경계를 유지하면서 재현된 문제만 고친다. A는 남은 문서 불일치를 닫지 못하고 C는 새 권한·이행 위험을 도입한다. 이 기술 판단을 사용자 직접 선택으로 쓰지 않는다. 최초 G4/G5 계약 snapshot은 독립 PASS였고, 아래 실험 후 운영 결정은 별도 재검토 대상이다.

### ADR: 규범 출처와 관찰 가능한 검사만 확장

**Context** — v1 AR-01~03은 순수 코어·오프라인 평가·당시 문서 정렬을 마쳤다. 남은 승인 문구와 구조도 표현, `check-harness.mjs`가 fragment를 버리는 앵커 검사 결함, 훅 실제 발화, 효과 측정의 정합성이 남았다.

**Decision** — `lifecycle.md` §5를 권한 규범으로 유지한다. 문서와 구조도는 실행 요약과 링크를 제공한다. 앵커는 상대 Markdown의 실제 제목/명시적 앵커와 로컬 HTML의 `id`를 검사한다. 외부 URL을 새로 검사하지 않고, 지원하지 않는 로컬 fragment를 성공으로 표시하지 않는다. 기본 대상 `--hook`의 성공 snapshot cache는 안전한 후보를 만들고 같은 workload로 측정했다. 후보는 full 12회 중 6회를 재사용했지만 시간 단축이 입증되지 않고 운영 복잡도에 비해 이득이 작아 채택하지 않는다. 운영 checker는 원래 full 경로로 복원한다.

**Alternatives** — A는 변경이 가장 작지만 규범 중복과 측정 공백을 남긴다. C는 단일 시스템처럼 보일 수 있으나 schema·설치 호환·보안 판단의 새 위험을 만든다.

**Consequences** — 문서·뷰 여러 파일을 함께 수정해야 하고 브라우저 확인이 필요하다. 앵커 slug·중복 제목·코드 펜스·percent encoding의 회귀가 필요하다. 후보 cache는 사용자 전용 OS 임시 저장소에 full 성공 후 원자 기록하고 변경·손상 시 full로 복귀했지만, 이 동작은 보존된 실험 증거다. 운영에는 cache record나 쓰기 추정에 따른 생략을 남기지 않는다. native hook 발화는 별도 관찰 전 `unknown`이고, 토큰·비용 telemetry는 `unknown`이다. G4/G5 계약 감사, 구현 AC, 운영 채택 판단을 구분한다.

## [GATE 3] 포함·제외 범위 · policy-delegated

- 포함: AR-04의 규범 정렬, AR-05의 재현 기반 도구 검토·필요한 최소 수정, AR-06의 동일 workload 측정·증거 갱신. 기본 4파일 예산 초과는 규범·파생 뷰·게이트 문서의 동시 정합성 때문이며 신규 의존성은 0개다.
- 제외: 새 승인 인증·`verified` 발급, STOP/예산 완화, 훅 무조건 비활성화, 모든 Markdown 렌더러를 지원하는 범용 파서, SaaS·유료 judge·원격 telemetry, 원본 로그 변경/삭제, 새 앱 UI, PR/병합/배포.
- Git 커밋·푸시 권한은 이 게이트 판단과 별개다. 메인이 같은 작업의 기존 사용자 원문과 현재 `master`·`origin` 대상을 확인해 이 재설계 완료분에 유효하다고 판정했다. PR·병합·배포는 포함하지 않는다.
- 목적·비용·보안 영향이 달라지거나 필수 검사·출처 확인을 약화해야 하면 해당 결정으로 돌아간다.

## 검증 상태

G2/G3은 승인된 재설계 결과 안의 AI 기술·범위 판단으로 기록했다. [잔여 이슈](issues-closure.md)와 [G5 시나리오](tests/closure-scenarios.md)의 최초 계약 snapshot과 cache 운영 불채택을 반영한 결정 snapshot은 각각 독립 G4/G5 PASS를 받았다. 검토 대상 해시는 [계약 증거](evidence/closure-contract.md)에 보존한다. 계약 PASS는 구현 AC나 최종 통합 검사 PASS가 아니다.
