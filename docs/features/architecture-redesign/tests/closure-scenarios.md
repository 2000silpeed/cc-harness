## CL-13 cache 실패 세부 oracle

아래는 보존 후보 checker의 격리 실험 oracle이다. 기본 호출은 후보 `node scripts/check-design-system.mjs --hook`, 명시 target은 그 뒤 경로를 붙인다. 각 행은 직전 성공 cache SHA·파일 mode(디렉터리 0700/파일 0600)·프로그램 종료 코드·full 파싱 여부·stdout/오류 진단을 별도 로그로 남긴다. cache 파일을 바꿀 때는 측정용 격리 fixture의 경로만 사용한다. cache 문제가 있어도 디자인 실패를 성공으로 바꾸지 않는다. 운영 checker는 cache를 포함하지 않는다.

W2의 기준·후보 `--hook`과 후보 default full 오류·nonzero, 후보 성공 cache SHA 불변, 유효 바이트 복원 뒤 이전 성공 서명 재사용 허용은 CL-15로 별도 판정한다. 스크립트 로딩·파일 변경 경합의 절대 보안 보증은 이 fixture로 주장하지 않는다.

## [GATE 5] 판정 상태

AI가 시나리오를 작성했고 구현자와 분리된 검증자가 최초 계약 snapshot과 cache 실험 뒤 운영 불채택·CL-16을 반영한 snapshot의 부정 사례·통제 의존성·권한 경계를 각각 감사해 G5 PASS로 판정했다. 두 검토 대상 해시는 [계약 증거](../evidence/closure-contract.md)에 보존한다. 계약 PASS와 실제 Red/Green·구현 AC 판정은 별도 단계다.
