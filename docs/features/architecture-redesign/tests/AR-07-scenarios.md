# AR-07 G5 시나리오 · 계약 검토 대기

- 근거: [R10–R12/AR-07 AC](../quality-hardening.md), 시작 `0c96b80`, 기존 14 case [corpus](../../../../tests/fixtures/handoff-evaluations.json). 아래 Then은 구현 관찰이 아니라 사전에 고정한 기대다.
- 입력 계약: `prepare|decide|claim|receipt`의 기존 case 입력과 격리 config/record. 출력 계약: `result` 의미 필드, `transition.changed`(boolean), `transition.record` 관찰, 종료 코드와 실패 경로. 실행은 동기 CLI 종료와 state 파일 저장을 기다린다. Git 고정 역사 CLI와 현재 후보는 같은 fixture를 사용한다.
- 관찰 schema: 모든 case의 `result.decision`은 문자열. 해당 operation/case에서 계약상 반환하는 `reason`, `resume_condition`, `budget`, `next_skill`, `next_action`, `transfer`, `handoff_id`는 문자열, `idempotent`와 `launch_allowed`는 boolean이다. `ERROR`의 `error`는 문자열. 선택 필드를 새로 채워 비교하지 않으며 **없는 필드와 `null`은 다르다**. 전이를 반환하는 case의 `transition.changed`는 boolean이며 `lineage-wrong-predecessor`에는 전이가 없다. 기록이 존재하는 case의 `record.status`는 문자열, `sequence`·`task.used_rollovers`·`budgets.green.used`·`budgets.diagnostic.used`·`budgets.rework_count`는 정수, `checkpoint.next_action`은 문자열, `rollover.claim`·`rollover.receipt`는 명시적 `null` 또는 객체다. 객체 키 순서만 무시하고 의미값·타입·배열 순서는 정규화하지 않는다.
- 모든 case의 전달 입력 객체·config 파일은 전후 동일하다. `decide`는 record 저장 변화가 없다. `claim`/`receipt`의 정상 저장 변화는 입력 객체 불변과 별개다. 아래 `P/C/R/L`은 독립 expected의 record 관찰값을 짧게 적은 것으로 현재 후보 출력에서 복사하지 않았다.
