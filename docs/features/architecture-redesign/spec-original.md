# 아키텍처 재설계 원문 기록

## 사용자 원문과 시점

- 최초 요청에서 확인 가능한 원문 표현: “전체 프로젝트 재설계”, “시각화해서 HTML보고서”. 전체 문장 원문은 이 작업 컨텍스트에 전달되지 않아 복원하지 않는다.
- 이후 방향 결정 원문: “추천안으로가자”. 이는 당시 승인·증거 참조를 원본 복사 없이 metadata 계보로 보존하는 제안에 관한 결정이며, B안 아키텍처를 직접 선택했다는 뜻으로 확장하지 않는다.
- 이번 구현 승인 원문: “재설계 마무리 하고 구현 까지”. 이후 계속 지시 원문: “계속”. 두 문장은 추천된 재설계 결과의 가역적 로컬 완성과 검증을 허용한다.

## 제공 자료와 기존 결과

- 기준 저장소: `cc-harness`, 기획 착수 HEAD `ae9ff54c33518b77fc0de18feb217660303ac739`.
- 기존 시각 보고서: `docs/architecture/redesign-review-2026-09-30.html`. 현재 구조의 관찰, B안 추천, 5단계 전환은 보고서 작성 당시 **제안**으로 표시되었다.
- 참고 원칙: LangSmith의 오프라인 평가·피드백 철학, Fowler의 작은 동작 보존 리팩터링. 특정 SaaS 또는 책의 공식 절차를 채택하라는 요청으로 해석하지 않는다.
- 현재 dirty 항목 `docs/features/trusted-approval/`은 별도 작업 소유이며 이 기획 범위에서 수정하지 않는다.

## 권한 경계

현 세션의 로컬 가역 구현·검증 승인을 기록한다. Git 브랜치·커밋·push·PR·병합, 배포, 외부 쓰기, 유료 호출, 파괴적 작업의 승인은 기록되지 않았다.
