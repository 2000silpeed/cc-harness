# 아키텍처 재설계 잔여 범위 요구사항 v2 · 최신 G4/G5 계약 PASS

- 기준: [v1 요구사항](spec-fixed.md) R1–R6과 커밋 `228fea90465772bc737927f61fd3b560e4076d2a`의 AR-01~03 완료 상태. v1 계약·원본 로그는 수정하지 않는다.
- 승인 원문: [원문 기록](spec-original.md)의 “남은거 끝까지 해줘 멈추지마 전문가처럼 빡세게 일해”. 같은 재설계의 가역적 로컬 잔여 구현·검증 범위다. 아래 구체적 기술·순서·측정 방법은 AI가 정한 기본값이다.
- 사용자 가치: 운영자가 승인·STOP 규칙을 한 규범 출처에서 확인하고, 실제 결함이 확인된 검사만 고치며, 절감 주장은 같은 작업량의 관찰 수치로 판단한다.
- 새 제품 UI는 없다. `docs/architecture/index.html`과 재설계 HTML은 기존 계약의 파생 뷰다.

## 오류·권한·성능 경계

- 승인 파일의 `approved`나 해시는 사용자 승인 진위가 아니다. 호출자가 실제 원문·주체·범위·시점·철회를 CLI 밖에서 확인한다. 현재 인계 CLI는 로컬 상태·해시·STOP·증거·예산을 검사할 뿐 실행 권한을 발급하지 않는다.
- 인계 source/dirty·참조·기존 STOP·예산, AR-01~03의 149개 테스트와 14개 오프라인 평가, 로컬 이식·설치 회귀를 보존한다. 새 변경으로 실패하면 실제 원인을 고치고 재검증한다.
- 속도·토큰·비용 절감은 같은 작업량과 측정 범위가 성립한 항목만 주장한다. 관찰하지 않은 수치는 추정으로 채우지 않는다.
- 외부 SaaS·유료 호출·새 승인 issuer·보안 정책 완화·전역 설정·파괴적 작업·PR/병합/배포는 이번 로컬 구현 계약 밖이다. 같은 재설계의 Git 커밋·푸시는 메인이 [원문 권한·대상·범위](spec-original.md)를 대조해 유효하다고 판정했다.
- 공통 G4/G5 계약 감사 후 AR-04와 AR-05는 독립 소유로 병렬 구현할 수 있다. AR-06 측정은 AR-04와 AR-05 AC1–4의 독립 판정 이후 진행하고 AR-05 AC5는 측정·운영 채택 결정과 함께 판정한다. 각 변경은 작게 묶고 관련 검사를 거친다. 이전 Green만으로 새 작업을 통과 처리하지 않는다.

## 결정 출처와 검토 상태

G1의 목적·가치와 로컬 구현 방향은 위 사용자 원문과 v1의 유효한 결과를 잇는다. R7–R9의 세부와 AR-05 cache 실험안은 AI 기본값이었다. 같은 입력 실험 결과를 보고 운영 불채택을 AI가 결정했다. G2/G3 판단 근거는 [PRD v2](prd-v2.md)에 `policy-delegated`로 기록한다. 최초 계약 snapshot과 실험 후 결정 snapshot은 각각 구현자와 분리된 G4/G5 감사에서 PASS를 받았고 대상 해시는 [계약 증거](evidence/closure-contract.md)에 보존한다. 계약 PASS는 구현 AC·최종 통합 검사와 구분한다.
