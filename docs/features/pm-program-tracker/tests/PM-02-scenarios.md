# PM-02 · 프로그램 수정 계약과 테스트 시나리오

상태: G5 승인 완료. 계약 요약과 Red 진행 질문에 사용자가 “진행”으로 승인했다. 이번 범위는 실패 테스트·최소 stub이며 Green 구현은 별도다. 실제 결과는 [Red 기록](PM-02-red.md)을 따른다.

## 근거와 현재 구현

- issues.md PM-02 AC1–AC4, spec-fixed.md F01/F02·P01–P04·D20–D27, prd.md C안, design.md의 한 행 표시 승인을 따른다.
- src/domain/program.ts의 ProgramDraft/Input/Record와 validateProgramDraft를 재사용한다. src/data/program-repository.ts에는 list/create/close만 있으며 update는 없다.
- src/App.tsx는 등록과 전체 값 보기만 제공한다. 수정·대상 전환은 미구현이다. 한 행 9열·날짜 분리·말줄임을 보존한다.
- PM-01은 조밀한 목록 변경 후 단위 36개·브라우저 14개 통과했다. 사용자는 저장 유지·중복 오류·수정된 목록 디자인을 확인했다. Windows 실기기나 배포 검증은 아니다.

## UI 계약 제안

1. 프로그램명 버튼으로 수정 dialog를 열고 저장된 9개 필드를 채운다. 모듈·담당자·변경 유형의 전체 보기 동작은 유지한다. 긴 프로그램명은 편집 입력 외 전체 읽기 문구도 제공한다.
2. modal 뒤의 행은 조작할 수 없으므로 dialog 내부에 ‘편집할 프로그램’ 선택기를 둔다. 모듈/프로그램명을 함께 표시하고 여기서 다른 행으로 이동한다.
3. 취소·Escape·다른 대상 선택 시 미저장 변경이 있으면 폐기를 확인한다. 거절하면 대상·선택기·초안 유지, 수락하면 닫기 또는 새 대상 불러오기다. 원래 값으로 되돌린 초안은 변경 없음이다.
4. 저장 중에는 입력·대상 전환·취소·재제출을 막는다. 성공 후 같은 id의 행을 같은 위치에서 갱신하고 닫으며 해당 프로그램명 버튼으로 포커스를 돌린다.
5. 검증 오류는 인접 문구·첫 오류 포커스, 저장 실패는 지속 alert·모든 초안 필드 유지·재시도를 제공한다. 중복 충돌은 기존 행 수정을 안내하고 덮어쓰지 않는다.

## 함수·저장 계약 제안

새 계약이며 구현된 API가 아니다. 새 의존성·DB 스키마·원격 API는 추가하지 않는다.

- `createProgramEditDraft(record: ProgramRecord): ProgramDraft`: 동기 순수 함수. id를 제외한 9개 값을 복사하고 null 날짜만 빈 문자열로 바꾼다. 원본 불변, 기존 상태 보존.
- `validateProgramDraft(draft: ProgramDraft): ValidationResult`: 기존 계약 유지. 식별자 trim/uppercase, 필수·5상태·달력 날짜·계획 순서 검증. 상태와 날짜는 서로 자동 변경하지 않는다.
- `ProgramRepository.update(id: string, input: ProgramInput): Promise<ProgramRecord>`: 검증된 입력으로 존재하는 id만 갱신한다. id·행 수 불변, createId 미호출. 존재 확인·자기 자신 제외 복합 키 충돌 확인·쓰기는 하나의 readwrite 트랜잭션이며 oncomplete 후 resolve한다.
- `ProgramStoreError.code`: 기존 duplicate/storage에 not-found 추가. 없는 id는 자동 생성하지 않는다. not-found 시 초안 보존·재조회 안내, 폐기 동의 후 목록 재조회. 조용한 신규 저장 금지.
- duplicate는 다른 id와 정규화한 키가 충돌할 때만 발생한다. 자기 키 유지·대소문자/공백만 바꾼 수정은 허용한다.
- storage는 DB 열기·쓰기·abort 실패다. 기존 데이터·목록·초안을 보존하고 원시 오류·입력 전체를 로그에 출력하지 않는다.

## AC 대응·회귀·인계

- AC1: S01–S05, S11–S14, S18–S19. 중복·실패 보존은 기존 P01/P04도 따른다.
- AC2: S01, S06–S08. AC3: S09–S12. AC4: S15–S18.
- 등록·중복·오류 복구·조밀한 목록 회귀를 유지한다. 프로그램명 전체 보기 테스트는 승인 후 ‘수정 진입+전체 이름 접근’으로 변경하고 다른 필드 전체 보기는 유지한다.
- 테스트 배치: PM-02 신규 단위는 tests/unit/program-editing.test.ts로 분리해 기존 등록 테스트를 보존한다. 브라우저는 tests/browser/program-editing.spec.ts. 기존 Vitest/fake-indexeddb/Playwright 사용.
- 실패 주입은 격리 테스트 DB/context 내부에 한정한다. 실제 사용자 데이터를 삭제하거나 production 실패 스위치를 만들지 않는다.
- 삭제·간트·복원·Excel·탭 쓰기 제한·오프라인·자동 저장·편집 이력·종료 후 초안 복구는 제외한다.
- 실행 순서: 대상 Vitest/Playwright 검사 → 환경 오류 시 수정·재실행 → 최종 npm run check. 테스트 실행 증거·미도달 assertion은 Red 기록에 구분한다.
- G5 검토 요청: 프로그램명으로 수정 진입, dialog 내부 대상 이동과 폐기 확인, 위 저장 계약·테스트 범위. 이미 확정한 상태·날짜 규칙은 재인터뷰하지 않는다.
