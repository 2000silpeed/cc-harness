# PM-07 · 자동 실행 중단과 재개 조건

## 중단 판정

적용 지침 `.agents/skills/tdd-auto-loop/SKILL.md` 원문: **“Red: import 등 잘못된 실패 이유이면 STOP.”** 원문 프로필은 잘못된 테스트 실패를 기능 미구현 증거로 간주하지 않고 해당 자동 실행을 종료하도록 한다.

PM-07 첫 단위 실행에서 shared 수식 fixture의 `XLSX.CFB.find(...)`가 null이어서 `TypeError: Cannot read properties of null (reading 'content')`가 발생했다. 당시 위치는 `tests/unit/program-excel.test.ts:160:37`이었다. 제품 코드 미구현과 무관한 테스트 준비 오류다.

Red 에이전트는 그때 중단하지 않고 fixture 경로를 수정한 뒤 같은 명령을 재실행했다. 메인이 인계 문서의 오류 이력을 발견하고 감사 질문으로 이를 확인했다. 현재 수정된 테스트가 올바른 assertion으로 실패해도 이미 발생한 STOP을 없었던 것으로 취급하지 않는다. PM-07 Green 및 PM-08–PM-10을 시작하지 않았다.

## 증거의 한계

- 단위 실행은 총 2회였다. 첫 실행도 61 실패·12 통과였지만 그중 shared 수식 사례는 fixture 오류였다.
- 최초 JSON 파일은 에이전트가 동일 경로로 재실행하면서 덮어썼다. 최초 오류 설명은 Red 에이전트의 후속 감사 응답에 근거하며, 보존된 원본 로그라고 주장하지 않는다.
- 현재 `tmp/pm-07-red-unit.json`은 수정 후 61 assertion 실패·12 no-op 통과 결과다. 브라우저 5개는 Excel UI 미구현 실패다.
- 선행 PM-06까지는 단위 157·브라우저 80개 및 전체 검사 exit 0. PM-07의 실패 테스트가 추가된 현재 작업 트리 전체를 통과 상태로 보고하지 않는다.
- 공식 SheetJS 설치·감사 0건·100행 파서 사전 실험은 완료했지만 Excel UI·압축 검증·Worker는 미구현이다. 도메인 두 파일은 최소 stub이다.

최종 인계 검사 `npm run check`는 lint·디자인·하네스·서식을 통과한 뒤 단위 169 통과·61 실패로 exit 1이었다(`tmp/pm-final-check.log`). 실패 61개는 보존한 PM-07 미구현 Red다. 이 통합 실행의 뒤쪽 빌드·브라우저 단계는 실행되지 않았다. 마지막 별도 빌드는 통과했고, 마지막 전체 브라우저 통과는 PM-06의 80개다. `git diff --check`는 통과했다.

## 보존 상태와 다음 실행

기준 커밋은 `1a7d465`. PM-03–PM-06 완료 코드·검증 기록과 PM-07 준비 파일은 로컬 미커밋 상태로 보존한다. 푸시·배포·실제 사용자 데이터 삭제는 하지 않았다.

재개 시 수정된 fixture를 독립 검토하고, 테스트 수집·타입 검사를 먼저 확인한다. 기존 미커밋 완료분과 준비 파일을 분리 검토해 기준점을 명시적으로 정한 다음 PM-07 Red부터 새 실행한다. 실행별 로그 경로를 분리하여 이전 실패 증거를 덮어쓰지 않는다. Green은 아직 0회이며 남은 이슈는 PM-07–PM-10 총 4개다. 기존 사용자 요구사항이나 수락 기준은 완화하지 않는다.
