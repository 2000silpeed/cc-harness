# PM-07 · Excel 파서와 제한

## 위임과 선택

사용자의 자동 실행 승인 범위에서 메인이 기술안을 선택했다. 인터뷰 요구사항을 바꾸거나 사용자에게 별도 답변을 받은 것으로 기록하지 않는다. XLSX 처리·경계 테스트·Worker가 필요하므로 이 이슈는 기본 4파일 예산을 넘긴다.

- SheetJS CE 0.20.3의 공식 배포 URL을 package.json에 고정하고 잠금 파일의 무결성 값을 사용한다. 앱에서는 로컬 번들로 실행하며 업무 파일을 서버에 전송하지 않는다.
- 출처: [공식 설치 문서](https://docs.sheetjs.com/docs/getting-started/installation/nodejs/), [읽기 옵션](https://docs.sheetjs.com/docs/api/parse-options/). npm 레지스트리의 오래된 xlsx 패키지 대신 공식 배포본을 사용한다.
- 설치 시 새 의존성의 스크립트 실행은 하지 않았다. 기존 Git 훅을 우회한 것은 아니다. 설치 후 감사 취약점 0건(`tmp/pm-07-parser-audit.json`).
- 로컬 사전 실험: 한국어 포함 100행 파일 18,337 bytes 생성·읽기 성공. 약 18ms는 이 환경의 단일 관찰이며 Windows 성능 보장이 아니다. `tmp/pm-07-parser-probe.json`.

## 업로드의 기술 경계

템플릿 1시트·고정 9열을 지원한다. 업로드 1회는 최대 1,000행·셀 2,000자이며 전체 프로그램 저장 개수의 상한이 아니다. 파일은 2 MiB, ZIP 항목은 100개, 실제 해제 합계는 20 MiB·항목당 10 MiB를 기준으로 검증한다. 메타데이터 크기만 믿지 않고 스트림 해제량을 확인한다. 암호화·ZIP64·중복 경로 등 지원하지 않는 컨테이너는 오류로 안내한다.

파싱은 별도 Worker에서 제한 시간 5초로 실행하는 설계다. 취소·시간 초과·파싱 오류는 저장을 수행하지 않는다. 수식은 실행하지 않고 오류로 표시한다. 날짜는 날짜 전용 값으로 처리하며 1900/1904 체계와 Excel의 가상 날짜를 테스트한다.

이 문서 작성 시점에는 파서 설치·100행 실험만 완료했다. ZIP 제한·Worker·템플릿 UI·미리보기 구현과 검증 결과는 PM-07 시나리오 및 result 기록을 따른다. Excel 신규 행 저장은 PM-08이다.
