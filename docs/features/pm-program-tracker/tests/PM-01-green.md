# PM-01 · Green 구현과 검증

## 승인과 범위

사용자가 Red 결과와 Green 다음 단계 안내에 “진행해”로 승인했다. 기존 계약과 신규 테스트의 기대값은 유지했다. PM-00 브라우저 검사에서만 더 이상 유효하지 않은 ‘저장되지 않습니다’ 안내를 실제 등록 dialog·첫 필드 포커스 확인으로 이행했다. 빈 상태·반응형·키보드 검사는 유지했다.

## 구현

- src/domain/program.ts: 식별자 trim·대문자 정규화, 필수 값·5상태·달력 날짜·계획 순서 검증. 입력 불변, 선택 날짜 null, 계획과 실제 완료일 독립.
- src/data/program-repository.ts: IndexedDB programs 저장소와 복합 unique identity 인덱스. 트랜잭션 완료 후 성공, 중복·저장 오류 구분, 실패 시 기존 데이터 보존, 연결 종료·재시도.
- src/App.tsx: 등록 dialog, 초안·필드 오류·저장 실패 보존, 재시도, 저장 중 재제출 차단, 폐기 확인, 목록·새로고침 읽기. 실제 날짜를 별도 라벨로 표시한다.
- src/styles.css: 기존 PM 토큰 기반 옆 패널·좁은 화면 dialog·입력·오류·disabled 상태. 신규 의존성 없음.

## AC 검토

독립 읽기 전용 검토자 Nietzsche가 원문·구현·테스트를 검토했다. 실제 명령은 메인이 실행했다. 초기 unverified 및 포커스 결함 지적 후 재현·수정·검증을 수행했다. 아래는 메인이 최종 실행 결과와 합쳐 정리한 판정이다.

| AC                                  | 구현·증거                                                                          | 판정 |
| ----------------------------------- | ---------------------------------------------------------------------------------- | ---- |
| AC1 정규화·기본 상태·재열기         | domain S01/S03, repository S10, browser S16/S17                                    | pass |
| AC2 필수·중복 거부·기존 데이터 보존 | domain S02/S05, repository S11, browser S11 전체 목록 비교·오류 포커스             | pass |
| AC3 저장 실패·초안/목록 유지·재시도 | repository S14 transaction abort, browser S18 모든 초안 값·기존 목록 비교와 재시도 | pass |

동일 repository 큐의 동시 중복은 검증했지만 별도 브라우저 연결 간 경쟁은 미검증이다. 단일 탭 쓰기 권한은 PM-09 범위다. 기존 행 수정 안내는 PM-01 AC 원문에 없으며 수정 동작은 PM-02에서 구현한다.

## 경계와 인계

Green은 PM 전체 완료가 아니다. 수정·간트·검색·백업·Excel·다중 탭 쓰기 제한·오프라인 실행은 아직 구현하지 않았다. 브라우저 데이터 삭제로 유실될 수 있으므로 업무 원본은 별도 보관한다. Windows Chrome/Edge 실기기·200% 확대·사용자 최종 디자인 수락은 미검증이다. 커밋·푸시·배포는 하지 않았다.
