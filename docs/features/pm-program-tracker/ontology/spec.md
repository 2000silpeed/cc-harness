# PM 디자인 합성 입력

**상태: 디자인 검토용 초안. 요구사항 전체와 P01~P04는 사용자 최종 미승인. 앱 구현 승인이나 제품 검증 결과가 아니다.**

## 근거와 권한

- 요구사항 근거: [요구사항 검토본](../spec-fixed.md), [인터뷰](../interview.md)의 D01~D11.
- 이 문서는 원본 요구사항을 대체하거나 승인 상태를 변경하지 않는다. 이번 디자인 합성 입력 작성만 요청받았다.
- `brand_profile.json`의 개념·레이아웃·컴포넌트는 Brief Author의 디자인 제안이다. 인터뷰 합의와 디자인 작성자 판단을 구분한다.
- 상세 컴포넌트 계약의 예약 경로는 `design-system/component-contracts.json`이다. 이 경로의 파일은 아직 이 작업에서 작성하지 않았다.
- 색상·글꼴 체계는 Token Curator 후속 작성, 런타임·색상 검증은 main 담당이다. 이 초안에는 색 값이나 글꼴 시스템을 넣지 않는다.

## 제품의 실제 일

PM이 프로젝트 하나의 프로그램을 본인의 PC 한 대에서 웹브라우저로 직접 등록·수정한다. 어떤 프로그램을 누가 맡고 있고 어느 단계이며 언제 개발·이관할 계획인지를 목록과 간트에서 대조한다. 로컬 데이터를 다시 열어 이어서 사용하고 백업·복원할 수 있어야 한다. 계정·원격 서버·클라우드 동기화는 없다. 저장 기술·파일 형식·완전 오프라인 제공 여부는 미정이다.

동일한 모듈+프로그램명은 한 행이다. 추가 변경은 기존 행을 수정하며 변경 건별 새 행이나 변경 이력을 만들지 않는다. 담당자는 로그인 계정이 아니며, 모듈 LE의 약어 의미와 ODATA 연동 기능을 추측하지 않는다.

## 브랜드와 시각적 태도 · 제안

브랜드의 중심은 **정확하게 구분하고 조용히 대조하는 작업 장부**다. 멋진 기록 모음보다 매일 같은 프로그램 행을 다시 찾아 계획과 실적을 고치는 도구여야 한다. 문구는 짧은 한국어 업무 표현을 쓰고 날짜 필드의 ‘예정’과 ‘실제’를 생략하지 않는다. 한글을 지원하며 영문 메타데이터와 식별 값에 uppercase 변환을 강제하지 않는다.

Digital Atelier / Curated Archive는 사용자 지시대로 차분한 tonal layering만 참고한다. 바탕, 장부, 선택·편집 맥락을 절제된 표면 층위로 구분하는 방향이다. TIL·문서 아카이브의 정보 구조, 카드 피드, 문구, 팔레트, 글꼴, 로고를 가져오지 않는다. 외부 레퍼런스를 직접 열람한 결과라고 주장하지 않는다. 새로운 그림·이미지는 필요 없다.

## 주작업면 · 디자인 작성자 제안

1. **상단 작업바:** 짧은 도구 제목, 프로그램 등록, 백업, 복원. 프로젝트 선택·로그인·검색·필터·태그는 없다.
2. **동일 행 목록/간트:** 왼쪽 장부와 오른쪽 시간축을 함께 주작업면으로 둔다. 모듈·프로그램명이 각 시간축 행의 식별 기준이다. 행 순서·높이·세로 스크롤·선택 강조를 공유해 서로 다른 프로그램을 착각하지 않게 한다. 시간축 가로 스크롤 중에도 식별 정보는 유지하는 방향을 제안한다.
3. **등록·수정 패널:** 기본은 닫힘. 등록 또는 행 선택 후 수정으로 열며 현재 행과 목록 맥락을 남긴다. 식별 정보(모듈·프로그램명), 업무 정보(변경 유형·담당자·상태), 개발 계획(시작·완료 예정일), 실적(실제 개발 완료일), 이관 계획(이관 예정일)을 구분한다. 저장·취소를 제공한다. 필수 표시·초기 상태·검증 정책은 P01~P02 승인 전 확정하지 않는다.
4. **작업 피드백:** 현재 입력·저장·백업·복원 작업에 인접한 텍스트 안내를 제안한다. 알림 센터·활동 로그를 추가하지 않는다. 실패 시 보존·차단·확인 동작은 P04와 분리해 검토한다.

첫 화면에 히어로, KPI 카드, 별도 대시보드를 배치하지 않는다. 데이터가 없으면 등록 안내를 보여주며 가짜 레코드로 채우지 않는다. 데이터가 있으면 장부 헤더와 프로그램 행 및 시간축이 첫 화면의 중심이어야 한다. 목록에는 모든 관리 항목이 읽히도록 열 구분을 제공하되 정확한 열 폭, 최초 표시 열 배분, 패널 폭, 최소 지원 화면 크기는 검토 대상으로 남긴다. 좁은 화면에서도 목록과 간트의 행 대응을 깨는 독립 카드형 재배열은 피한다.

## 상태와 날짜 · 합의된 의미

- 상태는 `개발 대기 → 개발 중 → 개발 완료 → 테스트 완료 → 이관 완료`의 다섯 가지다. PM이 직접 선택하며 이전 단계로도 돌아갈 수 있다. 순방향만 강제하지 않고 날짜에 따라 자동 완료하지 않는다.
- ‘일정 미정’은 상태값이 아니다. 개발 시작 예정일 또는 완료 예정일이 없으면 등록을 허용하고 목록에 일정 미정을 표시하며 개발 막대를 그리지 않는다.
- 개발 막대는 개발 시작 예정일~개발 완료 예정일을 뜻한다. 실제 완료일이나 이관 예정일을 개발 막대의 시작·끝 값으로 대용하지 않는다.
- 개발 예정 기간과 함께 이관 예정일을 확인할 수 있어야 한다. 구체적인 표식 형태는 디자인 제안이며, 개발 막대 없이 이관 예정일만 표시하는 규칙은 P03 미승인이다.
- 상태는 한국어 텍스트로도 구분한다. ‘일정 미정’ 안내를 여섯 번째 상태나 실패 상태로 표현하지 않는다.

| ---------------- | --------------- |

| 개발 완료 예정일 | 미제공          |

이 예시에는 개발 막대가 없다. 실제 완료일이 있다고 개발 완료 상태를 추정하지 않으며 두 예정일을 임의 보완하지 않는다. 이관 단독 표식을 시안에서 보여주려면 반드시 ‘P03 검토 제안’으로 구분한다. 기본 상태를 개발 대기로 확정하지 않는다.

## 컴포넌트 범위 예약 · 상세 계약 미작성

아래 여섯 개만 core component scope로 제안한다. 상단 작업바는 이 구성요소와 기본 액션을 담는 레이아웃 영역이지 일곱 번째 core component 예약이 아니다. 상세 anatomy·입출력·키보드·포커스·토큰 연결 계약은 후속 Component Contract Author 소관이다. `needs-authoring` 상태에서 구현하지 않는다.

| 이름             | 역할                                      | 검토할 상태와 경계                                         |
| ---------------- | ----------------------------------------- | ---------------------------------------------------------- |
| ProgramLedger    | 프로그램 한 행의 정보와 선택을 표시       | 빈 목록, 데이터 있음, 선택 행, 일정 미정                   |
| ScheduleTimeline | 동일 행 좌표의 개발 기간과 이관 계획 대조 | 기간 있음, 개발 막대 없음, 선택 행; 이관 단독 표식은 P03   |
| ProgramEditor    | 등록·기존 행 수정 패널                    | 닫힘, 등록, 수정, 편집 중; 필수·중복·날짜 검증은 P01~P02   |
| StatusControl    | 수동 다섯 상태 선택과 이전 단계 복귀      | 다섯 상태 모두; 초기값 P01, 날짜 부수효과 P03              |
| BackupRestore    | 로컬 백업·복원 진입과 작업                | 대기, 백업 요청, 복원 요청; 교체 확인·잘못된 백업 처리 P04 |
| FeedbackRegion   | 현재 작업의 결과·오류 텍스트 안내         | 안내 없음, 결과 안내; 검증·저장·복원 실패 상세 P01~P04     |

키보드 접근과 명확한 레이블, 선택·상태의 비색상 표현, 패널 진입·종료 시 포커스 복귀는 접근성 디자인 제안으로 후속 계약에서 명세한다. 실제 동작이나 접근성 검증을 완료했다고 보고하지 않는다.

## 미승인 제안과 미정 사항

| ID  | 아직 사용자 결정이 아닌 내용                                                                                                                     |
| --- | ------------------------------------------------------------------------------------------------------------------------------------------------ |
| P01 | 모듈·프로그램명·상태 필수, 개발 대기 초기값, 앞뒤 공백 제거 후 동일 문자열 비교·대소문자 자동 변경 없음, 중복 충돌 저장 차단과 기존 행 수정 안내 |
| P02 | 달력에 없는 날짜와 역전 기간 거부, 같은 시작·완료일의 당일 일정, 계획·실적 불일치 자동 보정 금지                                                 |
| P03 | 상태 변경 시 날짜 자동 입력·삭제 없음, 재개발 실제 완료일 직접 수정, 개발 기간 없는 행의 이관 예정일 단독 표식                                   |
| P04 | 전체 목록 시점 백업, 복원 전 교체 확인, 손상·형식 불일치·중복 키 거부 및 기존 데이터 보존, 로컬 저장 실패 안내와 성공 오표시 방지                |

요구사항 전체 최종 승인도 여전히 대기 중이다. 브라우저·실행 방식, 완전 오프라인 여부, 저장 기술·백업 형식, 예상/최대 프로그램 수·허용 응답 시간은 정하지 않았다. 시간축 단위·초기 표시 기간·반응형 치수·실제 완료일 추가 시간축 표식도 이 초안에서 확정하지 않는다. 프레임워크·DB·라이브러리를 선택하지 않는다.

## 범위 밖

검색, 필터, 사용자 정의 정렬, 삭제·휴지통, 대시보드 KPI, 로그인, 다중 프로젝트, 태그, 간트 드래그 편집, 진행률 퍼센트, 보류·취소 추가 상태, 알림·승인 흐름, 프로그램 의존성, 인력·비용 분석, Excel 대량 업로드, 외부 시스템 연동, 팀 공동 편집, 원격 서버·동기화, 변경 이력은 넣지 않는다. 테스트 완료일·실제 이관 완료일을 새 필드로 추가하지 않는다.

## 디자인 검토와 후속 인계

- 첫 화면의 작업바 및 목록/간트 동시 노출, 행 대응 유지, 편집 맥락 유지, 계획·실적 구분을 향후 시안에서 직접 검토한다.
- 예정일 없는 예시의 개발 막대 미표시와 상태 미추정을 확인한다. P01~P04가 승인된 기본 동작처럼 표현되면 초안을 수정한다.
- Token Curator는 이 구조를 유지하며 색상·글꼴 체계를 작성하고 Component Contract Author는 예약된 여섯 컴포넌트 계약을 작성한다. 구체적인 색·글꼴은 이 문서가 선점하지 않는다.
- main이 합성 런타임과 색상 검증을 병행한다. 이 Brief Author 작업은 문서 입력 작성과 정적 검토만 수행하며 합성 실행·화면 렌더링·앱 기능·출시 준비를 보증하지 않는다.
- 원본 요구사항 수정, 커밋, 설치, 외부 접근, 앱 구현은 수행하지 않는다.
