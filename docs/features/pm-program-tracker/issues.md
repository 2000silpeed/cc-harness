## 기준과 실행 순서

- [PRD](prd.md), [요구사항](spec-fixed.md)의 D01–D33 및 AC01–AC20, [디자인](design.md)을 기준으로 한다.

- PM-00만 기반 준비다. 나머지는 저장·도메인·상태·UI·테스트를 사용자 동작 단위로 함께 구현한다. 시간은 분해 기준이지 납기 약속이 아니다.

## PM-00 · 실행·디자인·테스트 기반 준비

상태: 완료. 사용자 “아하 그렇지 좋아 1번 진행해”로 PM-00 착수 승인. [실제 검증 기록](pm-00-verification.md)에 결과·제한을 남겼다. PM-01 이후 기능 착수 승인은 포함하지 않는다.

- 유형: 기반 준비
- 근거: C안·디자인 계약
- 선행: 없음
- 범위: 실제 React/TypeScript 실행 진입점과 IndexedDB 테스트 경계를 준비한다. 기존 토큰과 테마를 연결하고 추가 기능 계약·TSX 검사 범위를 보완한다.

### 수락 기준

- [x] PM-00-AC1: Given / When / Then — 기반 구성 전, 실행·빌드·타입·테스트 명령을 실행하면, 성공 여부와 실제 명령이 기록된다.
- [x] PM-00-AC2: Given / When / Then — 빈 앱을 열면, PM 디자인 토큰을 사용한 빈 목록과 등록 진입점이 표시된다.
- [x] PM-00-AC3: Given / When / Then — TSX에 색상·간격 위반 fixture가 있으면, 확장 검사기가 위반을 감지하며 정상 fixture는 통과한다.

### 테스트·경계

- 테스트 접근: 설정 smoke·정상/위반 검사 fixture. 실패 테스트 → 최소 구현 → AC 검토 → 리팩터링·보안 검토 순서로 수행한다.
- 도구 버전·의존성은 구현 시 검증 후 선택. 임시 앱 골격을 제품 완료로 보고하지 않음.
- 예상 변경: 실행 설정·검사기·테스트 기반·추가 디자인 계약. 실제 경로는 PM-00 이후 정하며 가상 구현 경로를 기존 파일로 주장하지 않는다.

## 공통 완료 기준과 인계

- 기능별 스타일·상태·키보드 및 화면 검토를 해당 이슈에서 수행한다. 마지막에 디자인을 몰아서 붙이지 않는다.
- 각 AC → test-scenarios의 테스트 ID → 실제 테스트 결과를 연결한다. 현재 체크박스는 전부 미검증이다.
- 실패 저장·복원·업로드의 기존 데이터 보존과 새로고침 이후 지속성을 검증한다.
- 기능 검사·정적 검사·실제 훅 발화·사용자 시각 승인은 별도 증거로 기록한다.
- G4 승인 후 PM-00은 project-bootstrap/design-system, PM-01부터 test-scenarios → tdd-loop, 통합 후 e2e-write로 인계한다. 기술적 미정은 해당 선행 단계에서 해결하고 범위가 바뀌면 영향만 검토한다.
