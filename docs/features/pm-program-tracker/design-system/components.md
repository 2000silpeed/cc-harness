# PM 컴포넌트 계약

상태: 여섯 도메인 컴포넌트의 **저작 및 strict 구조 검사 완료**, 사용자 디자인 승인·앱 구현은 미완료.

권한 파일은 [저작 계약](../ontology/design-system/component-contracts.json)이다. 생성기의 컴포넌트 스펙은 `../ontology/build/system/components/`에 있고 직접 고치지 않는다.

모든 계약에는 anatomy, states, variants, props, interaction, data_contract, responsive, content_rules, tokens, accessibility가 있다. 실제 props의 필수 타입·저장 API는 구현 기술안에서 구체화한다.

## 공통 상태 규칙

## D33 추가 계약 · PM-00 저작 보완

아래는 D31–D33으로 승인된 동작의 구현 계약이다. 기존 생성 JSON을 덮어쓰지 않는 저작 확장이며, 생성기의 strict 검사나 실제 컴포넌트 구현 완료를 주장하지 않는다. 공통 색상·타이포·간격 문서와 tokens.css → runtime-theme.css 순서를 그대로 사용한다.

| 계약                 | 입력·출력 경계                                                               | 상태·동작·데이터                                                                                             | 접근성·반응형·검증                                                                                                                    |
| -------------------- | ---------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------- |

BackupRestore 확장: 버전 있는 전체 JSON을 내보내며 검색 결과만 내보내지 않는다. 복원은 검증·전체 교체 확인 후 적용하고 오류·취소 시 기존 목록을 보존한다. Excel 신규 추가와 구분한다. ScheduleTimeline 확장: 오늘의 월·이전/다음 월·오늘 이동, 조건 유지, 월 밖 행도 장부에 남긴다. ProgramEditor 확장: 미저장 변경 폐기 확인. 각 실제 props 타입은 해당 이슈의 test-scenarios에서 고정한다.

PM-00 화면은 빈 장부와 등록 안내 진입점만 제공한다. 버튼은 PM-01 미구현 안내를 보여주며 저장을 흉내내지 않는다. 실제 기능의 hover/disabled/error 상태는 해당 이슈에서 구현·검증한다.

### 공통 상태 적용

- hover는 보조 면으로 약하게 이동하되 정보를 hover에서만 노출하지 않는다.
- focus-visible은 주 액션색 2px 외곽선과 2px offset 제안. 표면의 장식선보다 우선한다.
- 로딩은 실제 비동기 작업이 있을 때만 표시한다. 완료를 기다리는 동안 중복 실행을 막고 현재 작업명을 알린다.
- disabled는 이유를 설명하고 명암만으로 판단하게 하지 않는다.
- 저장·복원 성공은 실제 작업 결과 확인 뒤 표시한다. UI 장식 테스트를 데이터 안전성 테스트로 대체하지 않는다.

## 범위 보호와 검증

기존 범위의 6개 primitive와 6개 계약이 일대일 연결되고 미저작 계약 0개, 미정 primitive waiver 0개다. D31로 추가된 검색·필터·삭제·Excel 업로드는 이 검증 범위에 포함되지 않는다. 세부 요구사항 확정 후 필요한 계약과 화면을 보완한다. 태그·로그인·KPI는 추가하지 않는다.

P01–P04에 연결된 상세 오류·복원 계약은 검토 가능한 **조건부 설계**이며 사용자 승인 전 실행하지 않는다. 생성된 contract_status=complete는 저작 구조의 완결성이므로 기능 승인이나 런타임 동작을 의미하지 않는다.

실제 앱 단계에서는 키보드 등록/수정, 긴 값, 일정 미정, 상태 역전, 손상 백업, 저장 실패를 확인한다. 현재 수행한 검사는 [검증 기록](../ontology/verification.md)에 한정한다.
