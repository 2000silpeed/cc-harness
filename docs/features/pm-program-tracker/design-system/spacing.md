# PM 간격·배치

상태: 디자인 제안. 간트의 행 대응과 조작 밀도를 기준으로 하며 샘플의 1.4rem 리듬을 강제하지 않는다.

| 용도                     | 값·토큰                  | 이유                        |
| ------------------------ | ------------------------ | --------------------------- |
| 라벨과 입력              | --ds-space-px-4          | 필드 연결                   |
| 버튼 내부·작은 요소 간격 | --ds-space-px-8 / px-12  | 조밀하지만 분리 가능한 조작 |
| 패널 필드 묶음           | --ds-space-px-16         | 식별·계획·실적 구분         |
| 데스크톱 외곽            | --ds-space-px-24         | 작업 면 확보                |
| 모바일 외곽              | --ds-space-px-16         | 좁은 화면 공간 확보         |
| 주요 영역 간격           | --ds-space-px-24 / px-32 | 카드 중첩 대신 여백         |
| 입력·버튼 최소 높이 제안 | 44px                     | 포인터/터치 조작            |
| 기본 데이터 행 높이 제안 | 48px 이상                | 긴 값에 따라 함께 확장      |
| 입력·버튼 모서리         | --ds-radius-sm = 4px     | 과도한 pill 제외            |
| 편집 패널 모서리         | --ds-radius-md = 8px     | 문맥 있는 보조 면           |

`--ds-space-4`는 생성기에서 **12px**이다. 샘플의 spacing.4=22.4px와 다르므로 혼용하지 않는다. PM은 의미가 명확한 `--ds-space-px-*` 별칭을 사용한다.

## 기계 검사 기준

padding·margin·gap과 논리 방향 속성의 허용 토큰이다. 값은 tokens.css에서 읽으며 높이·너비는 간격으로 취급하지 않는다. 0과 auto는 배치 예외다.

```json
{
  "tokens": [
    "--ds-space-px-4",
    "--ds-space-px-8",
    "--ds-space-px-12",
    "--ds-space-px-16",
    "--ds-space-px-24",
    "--ds-space-px-32"
  ],
  "keywords": ["0", "auto"]
}
```

## 반응형 제안

- 1200px 이상: 프로그램 식별 열을 유지한 장부+시간축. 편집 패널은 우측 360–420px 후보.
- 768–1199px: 세부 날짜 열은 가로 스크롤로 접근하고 장부/간트의 단일 세로 좌표 유지. 패널은 overlay로 전환.
- 390px 검토: 작업바 줄바꿈, 전체 폭 편집 dialog, 데이터 면 내부 가로 스크롤. 페이지 전체 가로 넘침은 금지. 같은 행의 대응 관계 유지.
- 테스트 폭 390/768/1440px는 디자인 검토 목표이며 지원 브라우저·최소 화면 크기 승인과 구별한다.
- 시간축의 초기 날짜 범위·주/월 단위는 아직 미정이다. 화면을 채우기 위해 과거 인터뷰 예시의 기간을 추정하지 않는다.

구분선은 시간 격자·입력·키보드 포커스처럼 기능적 의미가 있을 때만 허용한다. 장식용 행 구분은 면 차이와 정렬을 우선한다. 일정 막대는 의미 있는 SVG/table 좌표계로 정렬하고 별도 absolute 픽셀 위치 목록으로 행 대응을 흉내내지 않는다.

검증 상태: 토큰 존재 및 구조 계약 확인. 실제 레이아웃·행 높이·스크롤·모바일은 구현 후 검증.
